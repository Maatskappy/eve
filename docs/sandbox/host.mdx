---
title: "Host Sandbox"
description: "Run sandbox commands with this machine's shell and filesystem during local development."
---

`HostSandbox.environment()` runs sandbox commands with this machine's `bash`, against a real directory. The agent can use the tools you already have installed, such as `git`, `pnpm`, `tsc`, and `python`. It does not start a container or VM.

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";
import { HostSandbox } from "eve/sandbox/host";

export const environment = HostSandbox.environment();
export default defineSandbox(() => environment.open());
```

During `eve dev` and `eve eval`, [`DefaultSandbox`](/docs/sandbox/default) selects the host sandbox, so you need this file only to change its options or to use it outside development.

The host sandbox needs `bash` and runs on macOS and Linux. On Windows, opening it fails; run eve inside WSL or use [Docker](/docs/sandbox/docker).

## Not an isolation boundary

The host sandbox runs commands as the user that started eve, with that user's files, network access, and credentials. A command the agent runs can read, change, or delete anything you can. eve does not apply a network policy, and the session does not expose `setNetworkPolicy()`. Use the host sandbox only for agents and inputs you trust. For isolation, use [Docker](/docs/sandbox/docker) or [Vercel Sandbox](/docs/sandbox/vercel).

## Per-session directories

By default, each eve session gets its own workspace directory under `.eve/sandbox-cache/host/sessions/` in your app. eve builds a template from `agent/sandbox/workspace/` and the environment's `prepare` function, then copies it once for each new session:

```ts
import { defineSandbox } from "eve/sandbox";
import { HostSandbox } from "eve/sandbox/host";

export const environment = HostSandbox.environment({
  async prepare(sandbox) {
    const result = await sandbox.run({ command: "git init -q" });
    if (result.exitCode !== 0) throw new Error(result.stderr);
  },
});

export default defineSandbox(() => environment.open());
```

The directory name comes from the session id alone, so every open for a session, including a subagent that shares the sandbox, a keyed tool session, or another eve process on the same machine, finds the same directory. The template applies only when eve creates the directory: after you change `agent/sandbox/workspace/` or `prepare`, existing sessions keep their files, and new sessions start from the new template. Authored skills are the exception; eve refreshes them in every session after a rebuild.

eve deletes a session's directory when you call `sandbox.delete()` and when the session ends. If you delete it yourself, for example by removing `.eve`, the session's next sandbox access starts a fresh directory from the template, as after `sandbox.delete()`. Templates live under `.eve/sandbox-cache/host/templates/` and are pruned with other local sandbox templates.

## Shared directory

Pass `root` to run every session in an existing directory, resolved from your app root:

```ts
import { defineSandbox } from "eve/sandbox";
import { HostSandbox } from "eve/sandbox/host";

export const environment = HostSandbox.environment({ root: "." });
export default defineSandbox(() => environment.open());
```

eve never copies `agent/sandbox/workspace/` files into a shared root, never deletes it, including on `sandbox.delete()` and session end, and never creates it: if the root is missing, opening the sandbox fails until you create it or change `root`. Because eve does not prepare a directory it does not own, `root` and `prepare` cannot be combined. Sessions that share a root also share its files, so concurrent sessions can see and overwrite each other's changes. eve stages attachments and tool-result files under `.eve/attachments/` in the root and does not remove them when a session ends; delete that directory when you no longer need them.

## Paths

The workspace root is the directory where commands start: the per-session directory, or `root`. Relative paths in `sandbox.readTextFile()`, `sandbox.writeTextFile()`, and the other file methods resolve from it. Absolute paths refer to the same path on your machine.

Skill files are copied into a directory eve owns under `.eve/sandbox-cache/host/sessions/`, not into your home directory. Commands receive that directory as `EVE_SANDBOX_SKILL_ROOT`. The `read_file` tool and other file tools resolve `$HOME/.agents/skills/` paths to it, and loading a skill tells the model where its files are, opening the host sandbox if it is not open yet. A `bash` command that expands `$HOME` itself still sees your real home directory.

## Commands and environment variables

eve runs each command with `bash -c` in its own process group. Aborting a command kills the process group. `sandbox.stop()`, `sandbox.delete()`, and server shutdown kill every process group the session started that still has a running process, including background jobs such as `server > log &`. The `bash` tool records each command in a `jobs` directory inside the session directory, and these also kill those commands and anything a finished command left running in the background. If the eve process exits without shutting down, for example after `kill -9`, commands it started keep running.

Commands inherit the environment variables of the process that started eve, with these exceptions:

- Values eve loaded from your `.env` files. If your shell exports a variable that an `.env` file also defines with a different value, the command keeps your shell's value.
- Variables eve sets for its own runtime: `EVE_DEV`, `EVE_EVALUATION`, `EVE_BASE_URL`, `PORT`, and names starting with `EVE_DEV_`, `EVE_DEVELOPMENT_`, `EVE_EVALUATION_`, `EVE_MODEL_`, `NITRO_`, or `WORKFLOW_`.
- The agent's model credentials: `AI_GATEWAY_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and `VERCEL_OIDC_TOKEN`. Pass them through `env` if a command needs them.

eve also sets `AI_AGENT=eve`, `EVE_SANDBOX_JOB_ROOT`, and `EVE_SANDBOX_SKILL_ROOT`. The `env` you pass to `run()` or `spawn()` overrides inherited values.

See the [sandbox overview](/docs/sandbox) for managed workspace, skills, parent inheritance, and custom providers.
