---
title: "just-bash Provider"
description: "Build a sandbox provider on just-bash, a bash interpreter and virtual filesystem written in TypeScript."
---

eve no longer ships a just-bash sandbox provider. To run commands on your own machine during development, use the [host sandbox](/docs/sandbox/host), which [`DefaultSandbox`](/docs/sandbox/default) selects during `eve dev` and `eve eval`. For isolation, use [Docker](/docs/sandbox/docker) or [Vercel Sandbox](/docs/sandbox/vercel).

If you want [just-bash](https://www.npmjs.com/package/just-bash) itself, for example a shell with no native processes or commands written in TypeScript, define it as a sandbox backend with `defineSandboxBackend()` from `eve/sandbox/provider`. The backend only opens a just-bash shell over a directory; eve handles templates, sessions, seeding, and cleanup.

## Install just-bash

Add just-bash to your application:

```sh
pnpm add just-bash
```

The provider on this page targets just-bash 3.1.

## Write the provider

Save the provider in your application, for example in `agent/lib/`:

```ts title="agent/lib/just-bash.ts"
import { posix } from "node:path";

import { defineSandboxBackend } from "eve/sandbox/provider";
import { Bash, type CustomCommand, type IFileSystem, ReadWriteFs } from "just-bash";

export interface JustBashOptions {
  /** Commands written in TypeScript that every shell command can call. */
  readonly customCommands?: CustomCommand[];
  /** Replaces the session filesystem, for example to mount more directories. */
  readonly filesystem?: (session: IFileSystem) => IFileSystem;
}

export const JustBashSandbox = defineSandboxBackend<JustBashOptions>({
  name: "just-bash",
  workspaceRoot: "/workspace",
  // eve prepares one template directory per build and copies it into each session's directory.
  directoryTemplate: true,
  async open(ctx, options) {
    // eve stages PDFs up to 20 MiB, past just-bash's default 10 MB read limit.
    const root = new ReadWriteFs({ maxFileReadSize: Number.MAX_SAFE_INTEGER, root: ctx.directory });
    const fs = options.filesystem?.(root) ?? root;
    await fs.mkdir("/workspace", { recursive: true });
    const bash = new Bash({
      customCommands: options.customCommands,
      cwd: "/workspace",
      env: { HOME: "/home/agent" },
      fs,
    });
    return {
      instance: {
        exec: ({ command, cwd, env, signal }) =>
          bash.exec(command, { cwd, env: { ...env }, signal }),
        readFile: async (path) => ((await fs.exists(path)) ? await fs.readFileBuffer(path) : null),
        async writeFile(path, content) {
          await fs.mkdir(posix.dirname(path), { recursive: true });
          await fs.writeFile(path, content);
        },
        removePath: ({ force, path, recursive }) => fs.rm(path, { force, recursive }),
      },
    };
  },
});
```

## Use the provider

Select the provider in `agent/sandbox/sandbox.ts`:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { JustBashSandbox } from "../lib/just-bash";

export const environment = JustBashSandbox.environment();
export default defineSandbox(() => environment.open());
```

`DefaultSandbox` never selects a custom provider, so this file is required.

## How the provider works

The provider describes only the just-bash shell. eve's [sandbox backend contract](/docs/sandbox#sandbox-backends) does the rest:

- **Template:** with `directoryTemplate`, eve prepares one template directory per build under `.eve/sandbox-cache/just-bash/templates/` in your app. It writes `agent/sandbox/workspace/` files under `/workspace` and skill packages under `/home/agent/.agents/skills`, then runs the environment's `prepare` function there. eve rebuilds the template when those files or `agent/sandbox/sandbox.ts` change. Editing `agent/lib/just-bash.ts` alone does not rebuild it, so delete `.eve/sandbox-cache/just-bash/templates/` after changing the provider.
- **Sessions:** each eve session gets its own directory under `.eve/sandbox-cache/just-bash/sessions/`, passed to `open()` as `ctx.directory`. eve copies the template into it the first time the session opens, so existing sessions keep their files after a rebuild. A rebuild still replaces the session's authored skills.
- **Paths:** the session directory is the root of the just-bash filesystem. Commands start in `/workspace`, relative paths resolve from it, and `$HOME` is `/home/agent`.
- **Cleanup:** `sandbox.delete()` and session end delete the session directory. If the directory was removed outside eve, eve starts the session over with a fresh copy of the template.
- **Environment:** every command gets `AI_AGENT=eve` plus the `env` eve passes for that command.

## Add custom commands

just-bash runs only its own built-in commands, so use `customCommands` to give the agent commands written in TypeScript. Define them with `defineCommand()` from just-bash:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";
import { defineCommand } from "just-bash";

import { JustBashSandbox } from "../lib/just-bash";

const forecast = defineCommand("forecast", async (args) => ({
  exitCode: 0,
  stderr: "",
  stdout: `Sunny in ${args[0] ?? "San Francisco"}\n`,
}));

export const environment = JustBashSandbox.environment({ customCommands: [forecast] });
export default defineSandbox(() => environment.open());
```

A custom command runs inside the eve process with eve's permissions, not inside the virtual filesystem's boundary.

## Mount more directories

Use the `filesystem` option to wrap the session filesystem. This example mounts a host directory read-only at `/reference` with just-bash's `MountableFs` and `OverlayFs`:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";
import { MountableFs, OverlayFs } from "just-bash";

import { JustBashSandbox } from "../lib/just-bash";

export const environment = JustBashSandbox.environment({
  filesystem: (session) =>
    new MountableFs({
      base: session,
      mounts: [
        {
          filesystem: new OverlayFs({
            mountPoint: "/",
            readOnly: true,
            root: "/absolute/path/to/reference",
          }),
          mountPoint: "/reference",
        },
      ],
    }),
});
export default defineSandbox(() => environment.open());
```

Without `readOnly`, `OverlayFs` keeps writes in memory and never changes the host directory. Use `ReadWriteFs` instead to let the agent write to a mounted directory.

## Seed the template

Use the `prepare` option, which eve adds to every backend, to write files or run commands once in the template that new sessions copy:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { JustBashSandbox } from "../lib/just-bash";

export const environment = JustBashSandbox.environment({
  async prepare(sandbox) {
    await sandbox.writeTextFile({ content: "# Notes\n", path: "notes/README.md" });
  },
});
export default defineSandbox(() => environment.open());
```

## Limitations

- **No native processes:** commands run in just-bash's TypeScript interpreter. Binaries such as `git` or `node` from your machine are not available unless you implement them as custom commands. just-bash can add its own sandboxed `python` and `js-exec` commands through the `python` and `javascript` options of `new Bash()`.
- **No background jobs:** each command runs to completion before eve gets its output, so a command cannot keep running in the background between `bash` calls.
- **No network policy:** the session does not expose `setNetworkPolicy()`. just-bash network commands such as `curl` stay disabled unless you pass just-bash's `network` option to `new Bash()`.
- **Local disk only:** sessions live in your app's `.eve/` directory on the machine running eve. On Vercel Functions, a session directory lasts only as long as the function instance, so use [Vercel Sandbox](/docs/sandbox/vercel) there.
- **No template pruning:** old templates stay under `.eve/sandbox-cache/just-bash/templates/` until you delete them.

## Differences from the removed built-in provider

The just-bash provider that eve used to ship differed from this page's provider in three ways:

- **Network access:** it allowed full internet access to just-bash's network commands. To restore that, pass the same option where the provider creates its shell:

  ```ts
  const bash = new Bash({
    customCommands: options.customCommands,
    cwd: "/workspace",
    env: { HOME: "/home/agent" },
    fs,
    network: { dangerouslyAllowFullInternetAccess: true },
  });
  ```

- **Installation:** it installed the `just-bash` package into your application during `eve dev` when it was missing. Add `just-bash` to your dependencies yourself.
- **Template pruning:** it removed old templates automatically. Delete old directories under `.eve/sandbox-cache/just-bash/templates/` yourself, or remove `.eve/sandbox-cache/just-bash/` while no session needs its files.
