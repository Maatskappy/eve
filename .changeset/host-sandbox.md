Add `HostSandbox` (`eve/sandbox/host`), which runs sandbox commands with your machine's own `bash` and tools in a per-session directory under `.eve/sandbox-cache/host`, or in an existing directory with `root`. It is not an isolation boundary. `DefaultSandbox` now selects it during `eve dev` and `eve eval`, uses Docker otherwise, and fails when the sandbox opens in production without Vercel or Docker. Local self-modification now edits your app directory through it and can run `git`, `pnpm`, and `tsc`. The just-bash provider is removed. `eve/sandbox/provider` now exports `defineSandboxBackend()`, which turns a sandbox engine that can open, find, and remove a sandbox per session into a full provider, with eve handling seeding, `prepare`, skills, and cleanup; and `SandboxSessionGoneError`, which a `defineSandboxProvider()` provider's `resume()` throws so eve starts a fresh sandbox when the old one is gone.

To migrate, replace `JustBashSandbox` from `eve/sandbox/just-bash` with `HostSandbox` from `eve/sandbox/host`, or define just-bash as a sandbox backend with the guide at `/docs/sandbox/just-bash`, and remove the `justBash` option from `DefaultSandbox.environment()`. A `DefaultSandbox` `prepare` function now runs on your machine during `eve dev` and `eve eval`; if it assumes the eve sandbox image (for example `dnf` or `sudo`), pin `DockerSandbox` locally instead. If production runs outside Vercel without Docker, select a provider explicitly in `agent/sandbox/sandbox.ts`.
