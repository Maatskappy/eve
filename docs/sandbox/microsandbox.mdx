---
title: "microsandbox Provider"
description: "Build a sandbox provider that runs each session in a local microsandbox microVM."
---

eve no longer ships a microsandbox sandbox provider. For a local sandbox with isolation, use [Docker](/docs/sandbox/docker). To run commands directly on your machine during development, use the [host sandbox](/docs/sandbox/host), which [`DefaultSandbox`](/docs/sandbox/default) selects during `eve dev` and `eve eval`. In production on Vercel, use [Vercel Sandbox](/docs/sandbox/vercel).

If you want [microsandbox](https://www.npmjs.com/package/microsandbox) microVMs, define them as a sandbox backend with `defineSandboxBackend()` from `eve/sandbox/provider`. This page shows a backend that runs one microVM per eve session from any OCI image; eve handles seeding, sessions, and cleanup.

## Requirements

microsandbox runs on macOS on Apple Silicon and on Linux with KVM (`/dev/kvm`) and glibc. It runs the VMs on the machine running eve, so it does not work on Vercel Functions.

Add the SDK to your application:

```sh
pnpm add microsandbox@0.5
```

The provider on this page targets microsandbox 0.5. The SDK runs VMs with a runtime in `~/.microsandbox`, and its `isInstalled()` function reports whether that runtime is present. If it is not, install it once on each machine with the SDK's `install()`:

```sh
node --input-type=module -e "import { install, isInstalled } from 'microsandbox'; if (!isInstalled()) await install();"
```

## Write the provider

Save the provider in your application, for example in `agent/lib/`:

```ts title="agent/lib/microsandbox.ts"
import { createRequire } from "node:module";

import { defineSandboxBackend, type SandboxBackendInstance } from "eve/sandbox/provider";
import { isInstalled, Sandbox, type SandboxHandle, SandboxNotFoundError } from "microsandbox";

export interface MicrosandboxOptions {
  /** OCI image with bash, a `vercel-sandbox` user, and `/workspace`. */
  readonly image?: string;
  readonly cpus?: number;
  readonly memoryMiB?: number;
}

// eve's Docker sandbox uses the eve image tagged with the installed eve version.
const { version } = createRequire(import.meta.url)("eve/package.json") as { version: string };
const DEFAULT_IMAGE = `ghcr.io/vercel/eve:${version.replace(/\+.*$/u, "")}`;
const USER = "vercel-sandbox";

async function findVm(name: string): Promise<SandboxHandle | undefined> {
  if (!isInstalled()) return undefined; // Without a runtime, no VM can exist.
  try {
    return await Sandbox.get(name);
  } catch (error) {
    if (error instanceof SandboxNotFoundError) return undefined;
    throw error;
  }
}

const wake = async (vm: SandboxHandle) =>
  connect(
    vm.status === "running" || vm.status === "draining"
      ? await vm.connect()
      : await vm.startDetached(),
  );

function connect(vm: Sandbox): SandboxBackendInstance {
  return {
    async exec({ command, cwd, env }) {
      const out = await vm.execWith("bash", (b) => b.args(["-lc", command]).cwd(cwd).envs(env));
      return { exitCode: out.code, stderr: out.stderrBytes(), stdout: out.stdoutBytes() };
    },
    async readFile(path) {
      return (await vm.fs().exists(path)) ? await vm.fs().read(path) : null;
    },
    async writeFile(path, content) {
      // Write as the sandbox user so the agent owns the file and its parent directories.
      const script = 'mkdir -p -- "$(dirname -- "$1")" && cat > "$1"';
      const out = await vm.execWith("bash", (b) =>
        b.args(["-c", script, "write", path]).stdinBytes(Buffer.from(content)),
      );
      if (out.code !== 0) throw new Error(`Writing ${path} failed: ${out.stderr()}`);
    },
    async stop() {
      await vm.stop();
      await vm.detach();
    },
  };
}

export const MicrosandboxSandbox = defineSandboxBackend<MicrosandboxOptions>({
  name: "microsandbox",
  workspaceRoot: "/workspace",
  async open(ctx, options) {
    if (!isInstalled()) throw new Error("The microsandbox VM runtime is not installed.");
    const existing = await findVm(ctx.key);
    if (existing !== undefined) return { instance: await wake(existing) };
    try {
      const vm = await Sandbox.builder(ctx.key)
        .image(options.image ?? DEFAULT_IMAGE)
        .cpus(options.cpus ?? 1)
        .memory(options.memoryMiB ?? 1024)
        .user(USER)
        .env("HOME", `/home/${USER}`)
        .workdir("/workspace")
        .detached(true)
        .create();
      return { created: true, instance: connect(vm) };
    } catch (error) {
      // Another process created the VM first.
      const raced = await findVm(ctx.key);
      if (raced === undefined) throw error;
      return { instance: await wake(raced) };
    }
  },
  async find(ctx) {
    const vm = await findVm(ctx.key);
    return vm === undefined ? undefined : await wake(vm);
  },
  async remove(ctx) {
    const vm = await findVm(ctx.key);
    if (vm === undefined) return;
    await vm.stopWithTimeout(10_000).catch(() => vm.kill());
    await vm.remove().catch((error: unknown) => {
      if (!(error instanceof SandboxNotFoundError)) throw error;
    });
  },
});
```

## Use the provider

Select the provider in `agent/sandbox/sandbox.ts`:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { MicrosandboxSandbox } from "../lib/microsandbox";

export const environment = MicrosandboxSandbox.environment();
export default defineSandbox(() => environment.open());
```

`DefaultSandbox` never selects a custom provider, so this file is required.

## Choose an image

By default the provider boots `ghcr.io/vercel/eve:<version>`, where `<version>` is your installed eve version, the same image that eve's Docker sandbox uses by default. Pass `image` to use another image, and `cpus` or `memoryMiB` to size the VM:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { MicrosandboxSandbox } from "../lib/microsandbox";

export const environment = MicrosandboxSandbox.environment({
  cpus: 2,
  image: "ghcr.io/acme/agent-sandbox@sha256:...",
  memoryMiB: 2048,
});
export default defineSandbox(() => environment.open());
```

Any OCI image works if it has `bash`, a `vercel-sandbox` user with a home directory, and a `/workspace` directory that user owns. To build such an image, start from `ghcr.io/vercel/eve` in a Dockerfile, push it to a registry, and pass its reference as `image`.

## How the provider works

The provider describes only the microVM. eve's [sandbox backend contract](/docs/sandbox#sandbox-backends) does the rest:

- **Sessions:** each eve session gets one microVM named `ctx.key`, which eve derives from the app's storage path and the session id. `open()` connects to the VM when it is running, starts it when it exists but is not running, and creates it only when it does not exist. If creation fails and the VM exists afterward, because another process created it first, the provider connects to that VM.
- **Seeding:** when `open()` reports `created`, eve writes `agent/sandbox/workspace/` files under `/workspace` and skill packages under `/home/vercel-sandbox/.agents/skills` through `writeFile()`, then runs the environment's `prepare` function. If any of that fails, eve stops and removes the VM, so a later open creates it again. When separate eve processes open the same new session at the same moment, one of them can use the VM before seeding finishes.
- **Commands:** every command runs as `vercel-sandbox` with `bash -lc`, starting in `/workspace`, with `AI_AGENT=eve` plus the `env` eve passes for that command.
- **Lifecycle:** `sandbox.stop()` and server shutdown stop the VM, and its disk persists, so the next access starts it again. `sandbox.delete()` and session end remove the VM; `remove()` succeeds when the VM or the runtime does not exist.
- **Removed VMs:** if the session's VM was removed outside eve, `find()` returns `undefined`, and eve starts the session over: `open()` creates a new VM, which eve seeds.

## What this provider omits

The removed built-in provider did more than this page's provider. Add these pieces when you need them:

- **Streaming output and cancellation:** `exec()` waits for each command with `execWith()`, so eve receives output only when the command finishes, and aborting a command does not stop it. To stream, start the command with `execStreamWith()` and return `{ stdout, stderr, exited, kill }`: split its `stdout` and `stderr` events into two streams, resolve `exited` from its `exited` event, and call its `kill()` from `kill`.
- **Dockerfile builds and template snapshots:** the built-in provider built `agent/sandbox/Dockerfile` with Docker, pushed the image to a local registry, booted a template VM from it during preparation, ran the environment's `prepare` function there, and saved the VM as a microsandbox snapshot that session VMs booted from. This provider runs `prepare` in every new VM instead. To snapshot, use `defineSandboxProvider()` for full control: build and push the image in `prepare()`, create a temporary VM, run your setup, stop it, and capture it with `SandboxHandle.snapshot()`. Then create session VMs with `Sandbox.builder(name).fromSnapshot(...)` instead of `.image(...)`.
- **Saved state outside development:** the built-in provider snapshotted a session's disk when it captured state in production and restored it on reconnect. This provider relies on the stopped VM's disk on the same machine.
- **A cross-process creation lock:** the built-in provider held a file lock while it created, reconnected, or removed a session's VM. This provider resolves a creation race by connecting to whichever VM exists after its own creation fails, and the losing process can use the VM before the winner finishes seeding it.
- **Network policies:** the built-in provider accepted a `networkPolicy` open option, applied domain rules, and injected credentials into outbound requests. This provider leaves the VM's network at microsandbox's default and does not expose `setNetworkPolicy()`. Configure networking at creation with the builder's `network()`, `disableNetwork()`, or `secretEnv()` methods.
- **VM cleanup:** the provider removes a VM only on `sandbox.delete()` and session end. List leftover VMs with `msb ls` and remove them with `msb rm <name>`. VM names come from `ctx.key`, which includes the app's absolute path, so after you move or rename the app directory eve treats each session's VM as gone and creates a new one, leaving the old VMs behind.
- **Platform checks and installation:** the built-in provider checked the host platform and installed the SDK and runtime during `eve dev`. This provider only checks that the runtime is installed.

## Troubleshooting

| Symptom                                        | Check                                                                                 | Next action                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `The microsandbox VM runtime is not installed` | Whether `isInstalled()` from `microsandbox` returns `true` on the machine running eve | Run the install command from [Requirements](#requirements).           |
| Opening the sandbox fails on Linux             | Whether `/dev/kvm` exists and your user can open it                                   | Enable KVM for the host or VM, or use [Docker](/docs/sandbox/docker). |
| Commands fail with a permission or user error  | Whether the image has a `vercel-sandbox` user and a `/workspace` it owns              | Use `ghcr.io/vercel/eve` or an image built from it.                   |
