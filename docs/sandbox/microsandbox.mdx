title: "microsandbox"
description: "Build a sandbox provider that runs each session in a local microsandbox microVM."
---

eve no longer ships a microsandbox sandbox provider. For a local sandbox with isolation, use [Docker](/docs/sandbox/docker). To run commands directly on your machine during development, use the [host sandbox](/docs/sandbox/host), which [`DefaultSandbox`](/docs/sandbox/default) selects during `eve dev` and `eve eval`. In production on Vercel, use [Vercel Sandbox](/docs/sandbox/vercel).

If you want [microsandbox](https://www.npmjs.com/package/microsandbox) microVMs, build a provider for them with `defineSandboxProvider()` and `createSandboxSession()` from `eve/sandbox/provider`. This page shows a provider that runs one microVM per eve session from any OCI image.

## Requirements

microsandbox runs on macOS on Apple Silicon and on Linux with KVM (`/dev/kvm`) and glibc. It runs the VMs on the machine running eve, so it does not work on Vercel Functions.

Add the SDK to your application:

```sh
pnpm add microsandbox@0.5
```

The provider on this page targets microsandbox 0.5. microsandbox also needs its VM runtime, which the SDK installs into `~/.microsandbox`. Install it once on each machine:

```sh
node --input-type=module -e "import { install } from 'microsandbox'; await install();"
```

## Write the provider

Save the provider in your application, for example in `agent/lib/`:

```ts title="agent/lib/microsandbox.ts"
import { createHash } from "node:crypto";
import { existsSync } from "node:fs";
import { mkdir, rename, rm, writeFile } from "node:fs/promises";
import { dirname, join } from "node:path";
import { setTimeout as sleep } from "node:timers/promises";

import {
  createSandboxSession,
  defineSandboxProvider,
  type SandboxProviderHandle,
  type SandboxProviderSessionContext,
} from "eve/sandbox/provider";
import {
  isInstalled,
  Sandbox,
  type SandboxHandle,
  SandboxNotFoundError,
  SandboxStillRunningError,
} from "microsandbox";

export interface MicrosandboxOptions {
  /** OCI image with bash, a `vercel-sandbox` user, and `/workspace`. */
  readonly image?: string;
  readonly cpus?: number;
  readonly memoryMiB?: number;
}

type Artifact = { readonly templateKey: string };
type State = { readonly version: 1 };

const DEFAULT_IMAGE = "ghcr.io/vercel/eve:latest";
const USER = "vercel-sandbox";
const HOME = `/home/${USER}`;
const WORKSPACE = "/workspace";
const RESOURCES = "/eve/resources";

const hash = (value: string) => createHash("sha256").update(value).digest("hex").slice(0, 32);
const templateRoot = (storagePath: string, key: string) =>
  join(storagePath, "microsandbox", "templates", key);
// VM names are global on the machine, so the app's storage path namespaces the session id.
const vmName = (ctx: SandboxProviderSessionContext) =>
  `eve-${hash(`${ctx.storagePath}\0${ctx.session.id}`)}`;
const toStream = (body: Uint8Array) =>
  new ReadableStream<Uint8Array>({
    start(controller) {
      controller.enqueue(body);
      controller.close();
    },
  });

function requireRuntime() {
  if (!isInstalled()) {
    throw new Error(
      "The microsandbox VM runtime is not installed. Install it with " +
        `node --input-type=module -e "import { install } from 'microsandbox'; await install();"`,
    );
  }
}

async function findVm(name: string): Promise<SandboxHandle | undefined> {
  try {
    return await Sandbox.get(name);
  } catch (error) {
    if (error instanceof SandboxNotFoundError) return undefined;
    throw error;
  }
}

async function wake(vm: SandboxHandle): Promise<Sandbox> {
  return vm.status === "running" || vm.status === "draining"
    ? await vm.connect()
    : await vm.startDetached();
}

/** Returns the session's VM, or creates and seeds it. */
async function upsertVm(name: string, template: string, options: MicrosandboxOptions) {
  const existing = await findVm(name);
  if (existing !== undefined) return await wake(existing);

  let vm: Sandbox;
  try {
    vm = await Sandbox.builder(name)
      .image(options.image ?? DEFAULT_IMAGE)
      .cpus(options.cpus ?? 1)
      .memory(options.memoryMiB ?? 1024)
      .user(USER)
      .env("HOME", HOME)
      .workdir(WORKSPACE)
      .volume(RESOURCES, (mount) => mount.bind(template).readonly())
      .detached(true)
      .create();
  } catch (error) {
    // Another process created the VM first.
    const raced = await findVm(name);
    if (raced === undefined) throw error;
    return await wake(raced);
  }

  const seeded = await vm.shell(
    `mkdir -p "$HOME/.agents/skills" && cp -R ${RESOURCES}/workspace/. ${WORKSPACE}/ && ` +
      `cp -R ${RESOURCES}/skills/. "$HOME/.agents/skills/"`,
  );
  if (seeded.code !== 0) throw new Error(`Seeding the microVM failed: ${seeded.stderr()}`);
  return vm;
}

async function removeVm(name: string) {
  const vm = await findVm(name);
  if (vm === undefined) return;
  await vm.stopWithTimeout(10_000).catch(() => {});
  try {
    await vm.remove();
  } catch (error) {
    if (error instanceof SandboxNotFoundError) return;
    if (!(error instanceof SandboxStillRunningError)) throw error;
    await vm.kill();
    await vm.remove();
  }
}

function createHandle(name: string, vm: Sandbox): SandboxProviderHandle {
  return {
    sandbox: createSandboxSession({
      resolvePath: (path) => (path.startsWith("/") ? path : `${WORKSPACE}/${path}`),
      async spawn({ abortSignal, command, env, workingDirectory }) {
        const exec = await vm.execStreamWith("bash", (builder) =>
          builder
            .args(["-lc", command])
            .cwd(workingDirectory ?? WORKSPACE)
            .envs({ ...env }),
        );
        abortSignal?.addEventListener("abort", () => void exec.kill().catch(() => {}), {
          once: true,
        });

        let stdout!: ReadableStreamDefaultController<Uint8Array>;
        let stderr!: ReadableStreamDefaultController<Uint8Array>;
        const streams = {
          stdout: new ReadableStream<Uint8Array>({
            start: (controller) => void (stdout = controller),
          }),
          stderr: new ReadableStream<Uint8Array>({
            start: (controller) => void (stderr = controller),
          }),
        };
        const exited = (async () => {
          const events = exec[Symbol.asyncIterator]();
          let exitCode: number | undefined;
          try {
            for (;;) {
              // Read output that arrives just after the exit event without waiting for the stream to end.
              const next =
                exitCode === undefined
                  ? await events.next()
                  : await Promise.race([events.next(), sleep(100)]);
              if (next === undefined || next.done === true) break;
              const event = next.value;
              if (event.kind === "stdout") stdout.enqueue(event.data);
              else if (event.kind === "stderr") stderr.enqueue(event.data);
              else if (event.kind === "exited") exitCode = event.code;
            }
            if (exitCode === undefined) throw new Error("The command ended without an exit code.");
            stdout.close();
            stderr.close();
            return exitCode;
          } catch (error) {
            stdout.error(error);
            stderr.error(error);
            throw error;
          } finally {
            void events.return?.();
          }
        })();
        exited.catch(() => {});

        return {
          ...streams,
          wait: async () => ({ exitCode: await exited }),
          kill: () => exec.kill(),
        };
      },
      async readFile({ path }) {
        const fs = vm.fs();
        return (await fs.exists(path)) ? toStream(await fs.read(path)) : null;
      },
      async writeFile({ content, path }) {
        const bytes = Buffer.from(await new Response(content).arrayBuffer());
        // Write as the sandbox user so the agent owns the file and its parent directories.
        const result = await vm.execWith("bash", (builder) =>
          builder
            .args(["-c", 'mkdir -p -- "$(dirname -- "$1")" && cat > "$1"', "write", path])
            .stdinBytes(bytes),
        );
        if (result.code !== 0) throw new Error(`Writing ${path} failed: ${result.stderr()}`);
      },
      async removePath({ force, path, recursive }) {
        const flags = `${force === true ? "f" : ""}${recursive === true ? "r" : ""}`;
        const result = await vm.execWith("rm", (builder) =>
          builder.args(flags === "" ? ["--", path] : [`-${flags}`, "--", path]),
        );
        if (result.code !== 0) throw new Error(`Removing ${path} failed: ${result.stderr()}`);
      },
    }),
    async onRuntimeShutdown() {
      await vm.stop().catch(() => {});
      await vm.detach();
    },
    onSandboxDelete: () => removeVm(name),
    onSandboxStop: () => vm.stop(),
  };
}

export const MicrosandboxSandbox = defineSandboxProvider<
  MicrosandboxOptions,
  undefined,
  Artifact,
  State
>({
  name: "microsandbox",
  environment(options = {}) {
    async function open(ctx: SandboxProviderSessionContext, artifact: Artifact) {
      requireRuntime();
      const name = vmName(ctx);
      const template = templateRoot(ctx.storagePath, artifact.templateKey);
      return createHandle(name, await upsertVm(name, template, options));
    }

    return {
      async prepare(ctx) {
        const { skills, workspace } = ctx.resources;
        const templateKey = hash(JSON.stringify([workspace?.key, skills?.key]));
        const template = templateRoot(ctx.storagePath, templateKey);
        if (existsSync(template)) return { templateKey };

        const draft = `${template}.${process.pid}.tmp`;
        await rm(draft, { force: true, recursive: true });
        const trees = [
          { files: workspace?.files ?? [], path: "workspace" },
          { files: skills?.files ?? [], path: "skills" },
        ];
        for (const tree of trees) {
          await mkdir(join(draft, tree.path), { recursive: true });
          for (const file of tree.files) {
            const target = join(draft, tree.path, file.relativePath);
            await mkdir(dirname(target), { recursive: true });
            await writeFile(target, file.content);
          }
        }
        await rename(draft, template).catch(async (error: unknown) => {
          await rm(draft, { force: true, recursive: true });
          if (!existsSync(template)) throw error;
        });
        return { templateKey };
      },
      // An upsert on the session id: the image and template apply only when the VM is created.
      async start(ctx, _openOptions, artifact) {
        return { handle: await open(ctx, artifact), state: { version: 1 } };
      },
      // Recreates a VM that was removed outside eve.
      async resume(ctx, artifact) {
        return await open(ctx, artifact);
      },
      // The key finds the VM, so `state` may be null.
      async onSessionEnd(ctx) {
        requireRuntime();
        await removeVm(vmName(ctx));
      },
    };
  },
});
```

## Use the provider

Select the provider in `agent/sandbox/sandbox.ts`:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { MicrosandboxSandbox } from "../lib/microsandbox";

export const environment = MicrosandboxSandbox.environment();
export default defineSandbox(() => environment.open());
```

`DefaultSandbox` never selects a custom provider, so this file is required.

## Choose an image

By default the provider boots `ghcr.io/vercel/eve:latest`, the image that eve's Docker sandbox uses by default. Each eve release also publishes `ghcr.io/vercel/eve:<version>`; pin the tag that matches your installed eve version so the image does not change underneath you:

```ts title="agent/sandbox/sandbox.ts"
import { defineSandbox } from "eve/sandbox";

import { MicrosandboxSandbox } from "../lib/microsandbox";

export const environment = MicrosandboxSandbox.environment({
  cpus: 2,
  image: "ghcr.io/vercel/eve:0.82.0",
  memoryMiB: 2048,
});
export default defineSandbox(() => environment.open());
```

Any OCI image works if it has `bash`, a `vercel-sandbox` user with a home directory, and a `/workspace` directory that user owns. To build such an image, start from `ghcr.io/vercel/eve` in a Dockerfile, push it to a registry, and pass its reference as `image`.

## How the provider works

The provider follows eve's [custom provider contract](/docs/sandbox#custom-providers):

- **Preparation:** `prepare()` writes `agent/sandbox/workspace/` files and skill packages to a template directory under `.eve/sandbox-cache/microsandbox/templates/` in your app.
- **Sessions:** each eve session gets one microVM, named from a hash of the app's storage path and the session id. `start()` is an upsert: it connects to the VM when it is running, starts it when it exists but is not running, and creates it only when it does not exist. On creation, the provider mounts the template read-only at `/eve/resources`, then copies the workspace files to `/workspace` and the skills to `/home/vercel-sandbox/.agents/skills`. If creation fails and the VM exists afterward, because another process created it first, the provider connects to that VM.
- **Commands:** every command runs as `vercel-sandbox` with `bash -lc`, starting in `/workspace`. Aborting a command kills it.
- **Lifecycle:** `sandbox.stop()` and server shutdown stop the VM, and its disk persists, so the next access starts it again. `sandbox.delete()` and session end remove the VM. `onSessionEnd()` finds the VM from the session id, succeeds when it does not exist, and can run more than once.
- **Removed VMs:** eve's built-in providers report a sandbox that no longer exists so that eve starts a fresh one, but a custom provider cannot. If `resume()` throws, every sandbox call in that session fails with that error until the session ends. This provider's `resume()` creates and seeds a new VM instead. Initialization that `defineSandbox()` runs after `open()` does not run again for a recreated VM.

## What this provider omits

The removed built-in provider did more than this page's provider. Add these pieces when you need them:

- **Dockerfile builds and template snapshots:** the built-in provider built `agent/sandbox/Dockerfile` with Docker, pushed the image to a local registry, booted a template VM from it during preparation, ran the environment's `prepare` function there, and saved the VM as a microsandbox snapshot that session VMs booted from. To do the same, build and push the image in `prepare()`, create a temporary VM, run your setup, stop it, and capture it with `SandboxHandle.snapshot()`. Then create session VMs with `Sandbox.builder(name).fromSnapshot(...)` instead of `.image(...)`.
- **Saved state outside development:** the built-in provider snapshotted a session's disk when it captured state in production and restored it on reconnect. This provider relies on the stopped VM's disk on the same machine.
- **A cross-process creation lock:** the built-in provider held a file lock while it created, reconnected, or removed a session's VM. This provider resolves a creation race by connecting to whichever VM exists after its own creation fails. Add a lock, for example a file lock under `ctx.storagePath`, if your setup runs several eve processes against one machine.
- **Network policies:** the built-in provider accepted a `networkPolicy` open option, applied domain rules, and injected credentials into outbound requests. This provider leaves the VM's network at microsandbox's default and does not expose `setNetworkPolicy()`. Configure networking at creation with the builder's `network()`, `disableNetwork()`, or `secretEnv()` methods.
- **Template pruning:** the built-in provider removed old template directories and their snapshots. This provider never deletes templates under `.eve/sandbox-cache/microsandbox/templates/`, and it removes a VM only on `sandbox.delete()` and session end. List leftover VMs with `msb ls` and remove them with `msb rm <name>`.
- **Platform checks and installation:** the built-in provider checked the host platform and installed the SDK and runtime during `eve dev`. This provider only checks that the runtime is installed.

## Troubleshooting

| Symptom                                        | Check                                                                    | Next action                                                           |
| ---------------------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `The microsandbox VM runtime is not installed` | Whether `~/.microsandbox` exists on the machine running eve              | Run the install command from [Requirements](#requirements).           |
| Opening the sandbox fails on Linux             | Whether `/dev/kvm` exists and your user can open it                      | Enable KVM for the host or VM, or use [Docker](/docs/sandbox/docker). |
| Commands fail with a permission or user error  | Whether the image has a `vercel-sandbox` user and a `/workspace` it owns | Use `ghcr.io/vercel/eve` or an image built from it.                   |
